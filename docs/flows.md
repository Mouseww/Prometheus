# 流程编排（Flows 插件）

把常用的多步骤 Agent 工作拖成一张有向无环图，固化为可重复执行的 SOP。插件：`plugins/flows`，内置、可在设置里开关；仅服务端宿主可用（步骤是无人值守的 agent 运行）。

## 节点

| 类型 | 说明 |
| --- | --- |
| start | 入口，有且仅有一个。启动输入 = 该节点输出，提示词里用 `{{input}}` |
| agent | 一个步骤，一次无人值守的 agent 运行（新会话，可从画布或“运行记录”打开）。可设权限（只读/可编辑/完全）和模型 |
| condition | 分支。`ai`（让 agent 答 YES/NO）、`contains`、`regex`；出线必须标 是/否 |
| subflow | 调用另一条已保存的流程，作为一个步骤。输入模板留空则传上游输出；子流程的最终输出成为本节点输出 |
| end | 可选出口，汇总最终结果 |

提示词变量：`{{input}}` 启动输入，`{{prev}}` 直接上游输出，`{{节点ID}}` 指定节点输出。提示词没引用上游输出时，上游输出会自动追加到末尾。

## 执行语义

- 一个节点在所有入线都“落定”且至少一条“有效”时运行；未被选中的条件分支上的节点标为“已跳过”。
- 无依赖的分支并行运行，同时最多 3 个 agent。
- 任一步骤失败即终止整条流程，其余节点标为跳过；可随时取消。
- 流程结果 = 各 end 节点的输出（没有 end 则取末端节点）。
- 应用关闭时仍在运行的记录会被标为“应用关闭时中断”。

## 创建方式

1. **模板**：侧栏“流程编排”里有 5 个内置模板（代码评审、缺陷排查与修复、需求→方案+用例、发布前检查、每日简报），一键套用后在画布上随意改（`apps/web/src/lib/flowTemplates.ts`，中英文）。
2. **画布**：拖动节点；从节点右侧圆点拖到另一个节点连线（会拒绝成环的连线）；拖空白处平移，Ctrl+滚轮或右上角按钮缩放，“适应画面”；Ctrl+Z / Ctrl+Shift+Z 撤销重做（拖动一次、同一输入框连续输入各算一步）；Ctrl+S 保存。
3. **AI 生成**：描述流程，agent（只读）输出 JSON，经归一化与校验后在画布上打开，保存才生效。画布里的“AI 修改”可在当前流程上继续调整（可撤销）。
4. **对话工具**：`flow_create` / `flow_list` / `flow_run` / `flow_delete`。步骤权限、运行权限都不会超过当前对话已有的权限（走 `parentSessionId` 封顶）。

## 校验

`flowIssues`（`packages/protocol/src/flow.ts`）由编辑器和服务端共用：每个问题都带 `nodeId`/`edgeId`。保存或运行时若有问题，编辑器不发请求，而是高亮出错节点、选中第一个并滚动到它，左下角列出全部问题，点一条即可定位；服务端仍会再校验一次。

## 运行可视化

- 画布上：运行中的节点发光并显示计时，流入它的连线流动；完成的节点变绿并显示耗时和输出摘要；被跳过的分支变暗。
- 顶部进度条：`步骤 n/m`、正在执行的步骤、总用时、触发来源（手动/定时/对话）、会话入口。
- 列表页：运行中的流程卡片显示进度条和当前步骤。
- 流程保存后，之前的运行结果不再绘制（图已变化）。

## 定时触发

编辑器页眉的“定时”：每天固定时间（可选星期）/固定间隔（5 分钟～7 天）/仅一次，可设定时运行时的 `{{input}}`。规则同自动化：仅在应用运行期间触发；错过的每日/单次任务在下次启动时补跑（一天内），间隔任务直接跳过；流程仍在运行时跳过本次。复制流程不带定时。

数据存于插件数据目录的 `flows.json`（流程 + 最近 60 条运行记录）。

## 子流程

- 画布上的“子流程”节点（虚线框）选择要调用的流程；子流程在自己的工作区里运行，权限由它自己的各步骤决定，但封顶规则不变（对话触发时不超过该对话权限）。
- 子流程的运行记录单独保存（`parentRunId`），不出现在运行历史里；父流程的节点上显示 `流程名 · 子步骤 n/m`，选中节点能看到子流程每一步的状态，“打开子流程”跳到它的画布。
- 保存时校验：必须选流程、不能调用自己、不能形成循环（报错会给出链路，如 A → B → A）、目标不能已被删除；被引用的流程不能删除。运行时嵌套最多 3 层。
- 停止父流程会连带停止它启动的子流程；子流程失败则父节点失败。
- AI 生成时会把已有流程清单交给 agent，它可以直接使用 subflow 节点。

## 被其他功能调用

- **对话**：`flow_list` / `flow_run` / `flow_create` / `flow_delete`。
- **自动化**：任务的“运行内容”可选“一条流程”（流程的运行输入、定时沿用自动化的计划）；流程步骤使用各自的权限。运行记录里的摘要是流程最终输出。
- **流程自己的定时**：见上节；与自动化二选一即可，需要统一在“自动化”里管理时用后者。
