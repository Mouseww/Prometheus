# 个人助理

内置插件 `assistant`（设置 → Prometheus 插件里可以关闭）。让 Prometheus 除了"在项目里写代码"，也能当个人助理用：有一条长期的对话，有自己的家，需要动项目时把活派过去。

## 它是什么

- **一条长期对话**：侧边栏"新对话"下面的"个人助理"。每次点都回到同一条对话，它记得之前说过的。删掉这条对话后，下次点会重新建一条。长对话靠设置里的"自动压缩"保持可用，请保持开启。
- **自己的家**：`<数据目录>/plugin-data/assistant/home/`，在侧边栏里是"个人助理"工作区。里面有 `persona.md`（它的性格和办事规矩，可以直接编辑，不会被覆盖）和 `notes/`（它的笔记，下次对话时会带上笔记目录的索引）。
- **派活**：它在家里办问答、规划、整理、记录；需要看或改项目时，用 `assistant_delegate` 把一个明确的任务派到项目里另起一次运行，拿回报告。对话里显示成一张"派活"卡片：去了哪个项目、结果、实际权限，点箭头进入那次运行的对话。

## 权限

- 派出去的活，权限由**宿主**限定，**不会高于当前这个对话的权限模式**：计划/默认模式只读；"自动接受修改"可改文件；"绕过权限"才可能完全权限。申请得比允许的高，会被降下来，卡片和汇报里都会写明。
- 无人值守的对话（渠道消息、简报）本身就是只读，所以从里面派出去的活也是只读。
- 只能从家里派活，项目里的对话不能转包。
- 工具标成了"只读"，所以不会每次都弹确认；真正的限制在宿主那一层。

## 渠道入口

`POST /plugins/assistant/inbound`，和其他接口用同一个登录（`Authorization: Bearer <令牌>` 或登录 cookie）。

```json
{ "text": "今天有什么安排", "channel": "feishu:ou_123" }
```

返回 `{ ok, reply, sessionId, result }`。用来接 IM 机器人、手机快捷指令、脚本。手机上直接用 Prometheus 的 Android 客户端连服务器，侧边栏的"个人助理"和桌面上是同一条对话。

规则（宿主之外也有测试）：

- **只读**：不管消息说什么，这次运行只能查看、回答、规划。需要改动，它会告诉对方回到电脑前处理。
- 一次一条（正在回复上一条时返回 409），每分钟最多 20 条（429），单条最长 4000 字，请求体最大 64 KB。
- 如果你正在桌面上和它聊（对话正在生成），渠道消息返回 409，稍后重试即可。
- **没有内置 IM 适配器**：飞书、钉钉、企业微信、Telegram 的机器人需要各自的账号和公网回调，这里只提供稳定的入口，适配器放在你自己的桥接里，或以后单独做成插件。

## 每日简报

对它说"每天 8 点给我一份简报"，它会用 `assistant_briefing` 开启（这个操作会让你确认）。到点后在后台只读地生成，存成 `notes/简报-日期.md`；程序启动晚于设定时间时当天补一次；失败不会整天重试。

## 定时自动化的提议

它发现你重复做同一件事时，按 `persona.md` 的规矩，先说清楚打算怎么做，你同意后才用 `automation_create` 建立定时任务，不会擅自创建。

## 给插件作者的接口

`@prometheus/plugin-sdk` 新增：

| 接口 | 作用 |
|---|---|
| `ctx.openSession({cwd, name?, prompt?, model?, workspaceName?})` | 创建一条用户在场的对话（和"新对话"一样），可选地后台发出第一句 |
| `ctx.sessionExists(id)` | 对话是否存在 |
| `ctx.sessionAccess(id)` | 这个对话当前允许派出的最高权限 |
| `ctx.runAgent({..., parentSessionId})` | 代表某个对话办事；权限被宿主限定在该对话的权限以内；未知对话只读 |
| `ctx.runAgent({..., sessionId})` | 在已有的空闲对话里继续（运行期间无人值守，结束后恢复原状） |
| `AgentRunResult.access` | 实际给了什么权限 |
| 工具结果的 `details` | 会随消息传到界面，可用来渲染卡片 |

## 已知限制

- 派活的结果卡片在运行结束后才出现；运行中显示的是普通的工具卡片。
- 点"个人助理"需要宿主是服务端形态（桌面版、服务器版）；终端版没有这个插件。
- 简报和渠道消息使用当前默认模型。
- 渠道入口目前没有按渠道分别授权，持有登录凭据的人都可以发消息。
