# 团队 Hub

相关文档：[团队 Hub 在线服务](team-hub-online.md)（公开模式）、[租户运行时](team-hub-runtime.md)、[运行与部署](deployment.md)。设计背景见 `docs/superpowers/specs/2026-11-05-team-mode-*.md`。

## 什么是团队模式

团队模式让多人共用一个 Prometheus Hub（下称 Hub）。Hub 集中管理账号、企业与团队、团队工作区（Git 仓库）、会话旁观与授权、合并请求、日报、模型网关、配额和审计日志。

个人使用仍然是第一优先的使用方式。没有连接 Hub 的 Prometheus 与以前完全一样：本地会话、本地工具、本地 Agent 都不变，个人会话也永远不会上传到 Hub。只有在团队工作区里启动的会话才会被镜像到 Hub，见下文「成员使用」。

团队模式涉及两种角色：

- **Hub**：以 `--role hub` 启动的服务端，保存团队数据。它也可以为每位用户按需拉起隔离的租户实例（见[租户运行时](team-hub-runtime.md)）。
- **成员**：普通的 Prometheus，通过团队插件连接到某个 Hub。

Hub 与普通服务端是同一份代码，只是启动方式、数据目录和默认端口不同。

## 部署形态

### 小团队：一台机器，不需要 Docker

适合几人到几十人的团队。Hub 运行在一台 Linux、macOS 或 Windows 机器上。

```bash
pnpm install
pnpm --filter @prometheus/web build   # Hub 的网页由服务端静态提供
pnpm hub                              # 等价于 node src/main.ts --role hub（在 apps/server 下）
```

默认行为：

- 监听 `127.0.0.1:7421`。
- 数据目录为 `<PROMETHEUS_HOME>/plugin-data/team/hub`，`PROMETHEUS_HOME` 默认为 `~/.prometheus-hub`，即 Windows 上的 `%USERPROFILE%\.prometheus-hub\plugin-data\team\hub`。下文所说的「数据目录」都指这个路径。
- 数据库使用内嵌的 PGlite，数据在 `<数据目录>/pgdata`。

启动前至少设置 `HUB_PUBLIC_URL`（见下文「环境变量」）。之后打开 `http://127.0.0.1:7421/`，完成「首次设置」。

没有 Docker 时租户运行时的驱动选择是 `HUB_RUNTIME=auto`，依次尝试 docker、sandbox、restricted。Linux 上可以用 `sh scripts/hub-setup-sandbox.sh` 安装并自检沙箱；Windows 上需要管理员做一次性设置，详见[租户运行时](team-hub-runtime.md)。

### 局域网直接访问

不想配置反向代理时，可以让 Hub 监听局域网地址：

```bash
PROMETHEUS_HOST=0.0.0.0
PROMETHEUS_TOKEN=<至少 16 位的随机串>
HUB_PUBLIC_URL=http://<局域网 IP>:7421
```

监听非回环地址时必须设置 `PROMETHEUS_TOKEN`，否则服务端拒绝启动。局域网直连没有 HTTPS，只适合可信网络。

### 数据库：PGlite 还是 PostgreSQL

| 项目 | PGlite（默认） | PostgreSQL |
| --- | --- | --- |
| 配置 | 不需要 | 设置 `HUB_DATABASE_URL` |
| 数据位置 | `<数据目录>/pgdata` | 数据库服务器 |
| 适合 | 小团队、单机 | 多人使用，需要独立备份或高可用 |
| 验证状态 | 默认方式，本仓库的测试使用它 | 代码路径已实现，尚未对真实 PostgreSQL 服务器做端到端验证 |

使用 PostgreSQL 的示例：

```bash
HUB_DATABASE_URL=postgres://prometheus:<密码>@db.internal:5432/prometheus
```

Hub 启动时自动执行迁移。Hub 会使用应用角色（默认 `prometheus_app`，可用 `HUB_DB_APP_ROLE` 修改）执行查询，行级安全依赖这个角色。角色不存在时，Hub 会尝试 `CREATE ROLE`，并把连接用户加入该角色。如果连接用户没有足够权限，启动会失败并打印需要由管理员手动执行的 SQL。Hub 不会在行级安全未生效时静默继续运行。

### 反向代理与 HTTPS

多人使用时推荐 Hub 只监听 `127.0.0.1`，前面放一层 HTTPS 反向代理。nginx 示例：

```nginx
server {
    listen 443 ssl;
    server_name hub.example.com;
    # ssl_certificate / ssl_certificate_key 按实际证书填写

    client_max_body_size 25m;   # 会话转写最大 20MB，需要留出余量

    location / {
        proxy_pass http://127.0.0.1:7421;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;     # WebSocket（/plugins/team/ws 与 /rt）必须转发
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 3600s;
    }
}
```

要点：

- `HUB_PUBLIC_URL` 必须是用户实际访问的地址，例如 `https://hub.example.com`，末尾不要带斜杠。它用于邀请链接、邮箱验证与密码重置链接、令牌的签发方（issuer），也决定租户实例访问 Hub 的地址（`<HUB_PUBLIC_URL>/plugins/team`）。留空时这些链接都不正确，租户也无法回连 Hub。
- 反向代理必须转发 WebSocket 升级请求，否则实时更新与租户连接不工作。
- 当前版本的 Hub 没有信任 `X-Forwarded-For`，经代理部署时按 IP 的限流会把所有用户算到代理的地址上，见「已知限制」。

### 备份

数据目录中的内容：

| 路径 | 内容 | 备份要点 |
| --- | --- | --- |
| `secret.key` | 主密钥，加密模型网关与 BYOK 的 API Key | 必须备份。丢失后已保存的密钥无法解密。应与数据库备份分开保存 |
| `jwt.key` | 令牌签名私钥（0600） | 丢失后会生成新密钥，所有已签发的令牌失效 |
| `pgdata/` | PGlite 数据库 | 备份前先停止 Hub |
| `repos/` | 团队工作区的 Git 裸仓库 | 必须与数据库同一时间点备份 |
| `tenants/` | 租户实例的数据与工作目录 | 可选 |
| `tenants.secrets/` | Windows 沙箱租户账号的密码（DPAPI 加密） | 只能由运行 Hub 的 Windows 账号解开 |
| `setup-code.txt` | 首次设置码（0600） | 首个账号创建后自动删除 |

备份方法：

- PGlite：停止 Hub，整体复制数据目录。
- PostgreSQL：用 `pg_dump` 备份数据库，同时复制 `repos/`、`secret.key` 与 `jwt.key`，四者应来自同一时间点。

## 环境变量

下表列出 Hub 读取的全部环境变量。默认值以代码为准。服务端通用变量与 Hub 角色相关的变量放在前两组。

### 服务端与启动

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PROMETHEUS_ROLE` | 空 | 设为 `hub` 时以 Hub 角色启动，等价于 `--role hub` |
| `PROMETHEUS_PORT` | Hub 为 `7421`，普通服务端为 `7420` | 监听端口 |
| `PROMETHEUS_HOME` | Hub 为 `~/.prometheus-hub` | 数据根目录。Hub 数据位于其下 `plugin-data/team/hub` |
| `PROMETHEUS_HOST` | `127.0.0.1` | 监听地址。非回环地址必须同时设置 `PROMETHEUS_TOKEN` |
| `PROMETHEUS_TOKEN` | 空 | 服务端令牌，至少 16 位。非回环监听时必填。Hub 的接口由 Hub 自己的账号鉴权 |
| `PROMETHEUS_WEB_ROOT` | 随包的 Web 构建目录 | 网页静态文件目录。未构建 Web 时只提供接口 |

### 数据库与身份

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HUB_DATABASE_URL` | 空（使用 PGlite） | PostgreSQL 连接串。设置后不再使用 PGlite |
| `HUB_DB_APP_ROLE` | `prometheus_app` | 行级安全使用的应用角色名 |
| `HUB_SECRET_KEY` | 自动生成到 `secret.key` | 主密钥，32 字节的 base64。用于加密 API Key |
| `HUB_PUBLIC_URL` | 空 | 用户访问 Hub 的根地址，如 `https://hub.example.com`。生产环境必须设置 |
| `HUB_ORG_NAME` | `我的团队` | 首个账号创建时自动生成的企业名称 |
| `HUB_MODE` | `private` | `private` 为企业部署；`public` 为在线服务，见在线服务文档 |
| `HUB_BILLING` | 关闭 | 私有模式下设为 `on`、`1` 或 `true` 启用积分计费。公开模式始终开启 |
| `HUB_TRUST_PROXY` | 关闭 | 经反向代理部署时设置，让 Hub 用 `X-Forwarded-For` 识别真实来源 IP（登录、注册、发邮件的按 IP 限流依赖它）。`1` 或 `true`：信任直连的代理一跳，取它追加的最后一个地址。逗号分隔的 IP 或网段（如 `127.0.0.1,10.0.0.0/8`）：只在直连对端属于该列表时才信任该头，并从右往左跳过列表内的代理，适合多层代理。无效值会让启动失败。不要在没有代理的部署上开启，否则客户端可以伪造来源 IP |
| `HUB_DATA_DIR` | 空 | 只被 `scripts/hub-setup-sandbox.ps1` 读取，作为 `-DataDir` 的默认值，并不被 Hub 本身使用 |

### 邮件

| 变量 | 默认值 | 说明 |

| `HUB_SMTP_URL` | 空 | SMTP 地址，如 `smtps://user:pass@smtp.example.com:465`。未设置时邮件只写入日志，不会真正发出 |
| `HUB_MAIL_FROM` | `Prometheus <no-reply@localhost>` | 发件人 |

| 变量 | 默认值 | 说明 |

| `HUB_BYOK_ALLOWED_PORTS` | 空 | 公开模式下，除 443 外允许的端口，逗号分隔，如 `8443,9443` |
| `HUB_BYOK_BLOCK_PRIVATE` | 关闭 | 设为 `1` 时，私有模式也禁止用户网关指向内网地址 |

| 变量 | 默认值 | 说明 |
| --- | --- | --- |

### 租户运行时

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HUB_RUNTIME` | `auto` | 驱动：`auto`、`docker`、`sandbox`、`restricted`。显式指定的驱动不可用时直接报错，不会降级 |
| `HUB_TENANT_ROOT` | `<数据目录>/tenants` | 租户目录根 |
| `HUB_TENANT_IMAGE` | `prometheus:local` | docker 驱动使用的镜像，可用仓库根目录的 `Dockerfile` 构建 |
| `HUB_DOCKER_RUNTIME` | 空 | Docker 运行时，如 `runsc`（gVisor） |
| `HUB_TENANT_NETWORK` | `bridge` | docker 网络 |
| `HUB_TENANT_ENTRY` | 本仓库的 `apps/server/src/main.ts` | 进程类驱动启动的服务端入口 |
| `HUB_TENANT_CPU` | `1` | 每个租户的 CPU 核数 |
| `HUB_TENANT_MEM_MB` | `2048` | 每个租户的内存上限（MB） |
| `HUB_TENANT_IDLE_MINUTES` | `30` | 没有请求与连接持续多久后停止租户 |
| `HUB_TENANT_MAX` | `3` | 同一台机器上同时运行的租户数，超出排队 |
| `HUB_TENANT_DISABLED_TOOLS` | 自动检测 | 强制决定是否向 restricted 策略写入 `disabledTools`，`1` 或 `0` |
| `HUB_HANDOFF_TENANT_WAIT_MS` | 未设置时为 `60000` | 会话调用目标租户时，等待其上线的最长毫秒数 |
| `DOCKER_HOST`、`DOCKER_CERT_PATH` | Docker 标准变量 | Docker 引擎地址与 TLS 证书目录 |

## 首次设置

1. 首次启动 Hub 时，标准错误输出（启动日志）会打印：`尚无任何账号。首个账号的设置码: XXXX-XXXX-XXXX（同时保存在 ……/setup-code.txt）`。设置码也保存在数据目录的 `setup-code.txt` 中（权限 0600）。
2. 打开 Hub 首页，选择注册，填写设置码、邮箱、显示名和密码。该账号成为**运营方**（operator），并自动创建名为 `HUB_ORG_NAME` 的企业。
3. 首个账号创建后，设置码立即删除。设置码只在数据库中没有任何账号时有效。请尽快完成这一步，避免别人抢先注册。

运营方拥有所有企业与团队的全部权限。完成首次设置后，建议先做以下事情（均在管理后台完成，见下一节）：

- 在「注册策略」中决定成员如何加入（默认只能通过邀请）。
- 在「平台设置」中决定是否允许个人团队。
- 在「模型网关」中配置团队共用的模型接口，否则成员无法使用模型。

## 管理后台

管理后台的入口对运营方和企业管理员开放，各页面的可见范围如下：

| 页面 | 谁可以使用 | 作用 |
| --- | --- | --- |
| 用户 | 运营方；企业管理员只看本企业 | 搜索用户，审批待审批账号，禁用、启用、封禁，直接创建账号 |
| 注册策略 | 运营方（平台级）；企业管理员（本企业，在「企业与成员」中设置） | 决定能否自助注册、允许的邮箱域名、是否需要审批 |
| 邀请 | 有企业或团队管理权限的人 | 生成团队或企业的邀请链接 |
| 企业与成员 | 运营方；企业 owner 与 admin | 创建企业，管理成员与角色，设置企业注册策略 |
| 平台设置 | 运营方 | 允许个人团队，允许自助创建企业 |
| 审计日志 | 运营方（平台范围）；企业管理员（本企业） | 查看管理与协作相关的写操作记录 |
| 模型网关 | 运营方；企业管理员（本企业） | 配置平台或企业共用的模型接口 |
| 配额 | 运营方 | 按用户或企业限制 token 用量 |
| 用量统计 | 能进入管理后台的账号 | 按用户、企业、日期或模型汇总用量 |
| 一次性邮箱域名 | 运营方，公开模式 | 禁止使用的临时邮箱域名 |
| 运营（计费） | 运营方，计费开启时 | 订单、套餐、价格、兑换码，见在线服务文档 |
| 个人设置 | 所有用户 | 我的模型（BYOK）、积分与账单 |

租户实例与执行节点目前通过接口管理（`/api/admin/runtimes`、`/api/admin/nodes`），管理后台暂无对应页面，详见[租户运行时](team-hub-runtime.md)。

### 用户

- **审批**：`requireApproval` 为真时，自助注册的账号处于待审批状态，运营方或企业管理员批准后才能登录。
- **禁用与启用**：禁用后账号不能登录，已有的令牌在下一次请求时被拒绝。
- **封禁**：仅运营方可以执行。封禁会禁用账号，并立即停止该用户的租户实例。解封使用「启用」。
- **直接创建账号**：填写邮箱、显示名与初始密码，账号直接启用并加入指定企业。这种账号不记录邮箱验证时间，因此不能自助创建企业（见在线服务文档）。初始密码由管理员设定，请通过安全渠道告知用户。

### 注册策略

平台级策略的字段与出厂默认值：

| 字段 | 含义 | 出厂默认 |
| --- | --- | --- |
| `allowOpen`（开放注册） | 任何人都可以自助注册 | 关闭 |
| `allowedDomains`（允许的邮箱域名） | 开放注册关闭时，只有这些域名的邮箱可以自助注册 | 空 |
| `requireApproval`（需要审批） | 自助注册的账号要等待审批 | 开启 |
| `allowInvite`（允许邀请注册） | 允许通过邀请链接注册 | 开启 |
| `closed`（关闭自助注册） | 关闭所有自助注册，优先级最高。不影响邀请注册 | 关闭 |

因此出厂状态下，新成员只能通过邀请注册。要开放自助注册，需要开启「开放注册」或填写允许的域名，并根据需要关闭「需要审批」。注意：在公开模式下，即使关闭了审批，自助注册的账号也要先验证邮箱（见在线服务文档）。

邀请注册的账号直接启用，不需要审批，因为邀请本身就是审批。

### 邀请

- 为团队或企业生成邀请时，需要填写受邀人的邮箱和角色。企业角色为 `owner`、`admin`、`member`；团队角色为 `admin`、`reviewer`、`member`。
- Hub 返回形如 `<HUB_PUBLIC_URL>/invite/<token>` 的链接，**由管理员自行发送**，Hub 不会替你发邮件。
- 链接 7 天内有效，只能用于注册该邮箱的账号。注册时填写的邮箱必须与邀请邮箱一致。
- 公开模式下，邀请注册跳过人机验证与一次性邮箱检查，详见在线服务文档。

### 企业与团队

- **企业（organization）**：成员角色为 `owner`、`admin`、`member`。企业的 `owner` 与 `admin` 对企业下的所有团队拥有团队管理员的权限。
- **团队（team）**：成员角色为 `admin`、`reviewer`、`member`。
- **建团队**：企业团队由企业的 `owner` 或 `admin` 创建。个人团队由用户自己创建，私有模式下需要运营方在「平台设置」中开启「允许个人团队」，该设置默认关闭；公开模式下默认开启。
- **个人团队转入企业**：团队管理员发起转入请求，目标企业的 `owner` 或 `admin` 接受或拒绝，发起人可以取消。只有个人团队可以转入，同一团队同时只能有一个待处理的请求。
- **工作区（workspace）**：属于团队的 Git 仓库，包含默认分支、日报时间与时区等设置。

权限的主要规则如下（运营方拥有所有权限）：

| 操作 | 谁可以 |
| --- | --- |
| 旁观团队会话、fork 会话、开会话、提交合并请求 | 团队任意成员 |
| 审核（通过或拒绝）合并请求、跳过审核 | 团队 `admin`、`reviewer` |
| 创建工作区、修改工作区设置、管理团队成员 | 团队 `admin`（企业 `owner` 与 `admin` 隐含此权限） |
| 授权他人操作某个会话 | 仅会话所有者 |
| 创建企业 | 运营方（公开模式下的自助创建见在线服务文档） |

### 模型网关

- **格式**：`openai`（OpenAI 兼容）、`anthropic`、`gemini`。
- **字段**：名称、格式、Base URL、API Key、模型列表、启用开关。模型列表为空表示该网关接受任何模型。
- **范围**：平台（所有人可用）或企业（本企业成员可用）。
- **API Key 只写**：保存后接口只返回掩码，无法读出原文。密钥用主密钥加密保存（AES-256-GCM），主密钥即 `HUB_SECRET_KEY` 或 `secret.key` 的内容。
- **选择顺序**：成员自己的 BYOK 网关优先，其次是企业网关，最后是平台网关。
- 成员的 Prometheus 通过 Hub 的模型代理（`/llm/<格式>`）使用这些网关。上游 API Key 不会下发到成员机器或租户实例，成员端只拿到 Hub 签发的令牌。

### 配额

- 配额按用户或企业设置，周期为每天（`day`）或每月（`month`），单位为 token 数。设为空可清除。
- 超出配额后，模型代理拒绝该次调用。

### 用量统计与审计日志

- 用量统计可以按用户、企业、日期或模型分组，并指定起止日期。
- 审计日志记录账号、企业、团队、邀请、授权、合并请求、封禁、计费等写操作。企业管理员只能看到本企业的记录。

### 平台设置

- **允许个人团队**：私有模式默认关闭，公开模式默认开启（未显式设置时取模式默认值）。开启后，任何已启用的用户都可以创建个人团队。
- **允许自助创建企业**：只影响公开模式，默认开启。见在线服务文档。

## 成员使用

### 连接 Hub

1. 在个人 Prometheus 的团队页面填写 Hub 地址，例如 `https://hub.example.com`，然后登录。若注册策略允许，也可以在此注册。
2. 登录后可以看到你所在的企业、团队与工作区。
3. 团队的本地目录由插件设置 `teamRoot` 决定，默认为 `~/PrometheusTeams`。工作区的源副本位于 `<teamRoot>/<团队>/<工作区>/.repo`，每个团队会话在其下的独立 worktree 中运行。

### 团队会话

- 在团队工作区里新建会话，会话会在该工作区的独立 worktree 与分支中运行。
- 只有 cwd 位于团队 worktree 内的会话才是团队会话。团队会话会被镜像到 Hub，包括消息、工具调用摘要、运行状态、转写快照与文件快照。个人会话永不上传。
- 团队会话固定使用 PI 运行时，模型使用团队模型提供方（即 Hub 的模型网关）。
- 文件快照会忽略 `node_modules`、`dist`、`build`、`target`、`bin`、`obj` 等构建目录。
- 会话状态有四种：`running`（运行中）、`waiting`（等待权限确认）、`idle`（空闲）、`offline`（成员与 Hub 断开超过 60 秒）。

### 旁观

团队的所有成员都可以在看板与会话列表中查看团队内全部会话的状态、事件记录和快照文件，但只能查看，不能操作。

### 授权与远程操作

- 会话所有者可以把某个会话授权给团队成员。只有所有者能授权或取消授权。
- 被授权人可以在网页上对该会话发送消息、回应权限请求、中断运行。这些操作经 Hub 转发到当前执行该会话的一端：会话在所有者电脑上执行时发往电脑，移交到团队 server 后发往所有者的租户实例（授权检查相同）。所有者在已移交的另一端副本里输入的消息，同样经 Hub 转发到当前执行的一端。
- 所有者离线时，操作返回「会话所有者当前不在线」。所有者在 30 秒内没有响应时，操作超时。
- 被授权人发送的消息会带上 `[来自 <名字>]` 前缀，并记入审计日志。

> **授权前请注意：授权等同于让对方驱动你本机上的 Agent。** 被授权人转发的「发送消息」「回应权限请求」「中断」会直接作用于你电脑上正在运行的会话。「回应权限请求」包括批准该会话在你电脑上申请的权限（例如执行命令、写文件），也就是说，被授权人可以让你的 Agent 以你的账号权限在你的电脑上做事。只把会话授权给你信任的成员，用完及时取消授权。

### 本机操作确认

团队 server 上的租户实例通过 `local_read`、`local_ls`、`local_grep`、`local_exec` 访问你的本机。每次调用都会在你的界面上弹出确认卡片，120 秒内没有回应按拒绝处理。

- 只读工具（读取、列目录、搜索）可以选择「本会话允许」。它只对该会话内、路径真实位置（解析符号链接后）仍在项目工作副本之内的调用生效，每次调用都会重新检查路径；访问工作副本之外的路径时仍会询问。
- 执行命令（`local_exec`）不提供「本会话允许」，每条命令都要确认。确认请求里带有 `allowSession` 字段（`false` 表示界面应隐藏该按钮；即使客户端仍发送 `session`，也按「仅此一次」处理）。
- 同一个 `callId` 在等待确认期间再次出现时会被拒绝（`duplicateCallId`），不会覆盖正在显示的确认卡片。
- `local_grep` 的正则最长 512 个字符，不支持反向引用，也不接受「被重复的分组内再含重复或分支」的写法（如 `(a+)+`、`(a|aa)*`），以避免灾难性回溯；每行最多匹配前 2000 个字符。

### Fork

团队成员可以 fork 自己能看到的团队会话：

- 系统基于原会话的最新快照创建新的 worktree 与分支，导入原对话记录，之后在自己的电脑上继续。
- 原会话所有者会收到通知。
- 对话记录超过 20MB 时不会上传，该会话无法完整 fork。

### 合并请求

1. 在团队会话中完成修改后，提交合并请求，填写标题和说明。成员插件会先把 worktree 中的改动提交到会话分支并推送。
2. Hub 检测与默认分支的冲突，使用 `git merge-tree`。这需要 Git 2.38 或更高版本，否则合并功能会被禁用。
3. 无冲突的请求进入待审核状态。团队 `admin` 或 `reviewer` 可以通过或拒绝。通过时，Hub 生成合并提交并更新默认分支。
4. 团队 `admin` 或 `reviewer` 创建请求时可以选择「跳过审核」，请求直接合并。
5. 有冲突时，在本机 worktree 中 `git fetch` 后合并或变基默认分支（可以让 Agent 帮忙），推送后调用「刷新」重新检测。二进制文件冲突可以选择「保留我的」或「保留团队的」。

合并请求的状态：

| 状态 | 含义 |
| --- | --- |
| 待审核（open） | 等待审核 |
| 冲突（conflict） | 与默认分支冲突，需要先解决 |
| 已合并（merged） | 已合并到默认分支 |
| 已拒绝（rejected） | 审核人拒绝 |
| 已关闭（closed） | 作者或管理员关闭 |

### 看板与日报

- **看板**：每位成员的会话（状态、最后活动时间），待审核的合并请求，以及最近的合并记录。
- **日报**：每个工作区可以设置生成时间（默认 `09:00`）、时区（默认 `Asia/Shanghai`）与开关（默认开启）。日报汇总前一天的会话标题、首条消息、助手的最后输出、工具调用次数，以及合并请求的创建、合并、拒绝与冲突，并按成员分组。
  - 如果有可用的模型网关，日报由模型生成结构化总结。否则生成基于规则的摘要。
  - 团队管理员可以手动为某一天生成日报。

### 上游远程（可选）

工作区可以配置一个上游 Git 地址，仅支持 HTTPS，令牌加密保存。配置后，Hub 会把默认分支同步到上游。

### 本地 Hub（单机试用）

成员插件提供「本地 Hub」选项，会在本机启动第二个 `--role hub` 进程，使用独立的数据目录和随机令牌，端口为 7421。适合在一台电脑上体验团队模式。

## 安全说明

- **行级安全（RLS）**：团队相关的表启用了行级安全。每个请求的事务先切换到应用角色，再把当前用户与运营方标志写入会话变量，策略据此决定用户能看到哪些企业、团队与会话。后台任务使用系统身份，不受这些限制。
- **密钥只写**：模型网关与 BYOK 的 API Key 只能写入，接口只返回掩码。主密钥来自 `HUB_SECRET_KEY`，未设置时自动生成到 `secret.key`。
- **令牌有效期**：访问令牌 15 分钟，刷新令牌 30 天。租户访问 Hub 的凭据 30 天（受众 `prometheus-tenant`）。租户访问模型网关的令牌 7 天。令牌不能单独吊销，但账号被禁用或封禁后，Hub 会在下一次请求时拒绝该账号。
- **文件权限**：`secret.key`、`jwt.key` 与 `setup-code.txt` 以 0600 创建。数据目录只应允许运行 Hub 的账号访问。
- **审计**：封禁、授权、合并、计费、邀请等操作都会写入审计日志。
- **策略文件**：Hub 为每个租户生成 Prometheus 策略文件（`policy.json`）。常用的键如下：

| 键 | 含义 |
| --- | --- |
| `serverOwner` | 服务端所有者的用户 ID。租户实例中即该用户 |
| `forbiddenModes` | 禁止切换到的权限模式。Hub 租户默认禁止 `bypassPermissions` 与 `auto` |
| `defaultPermission` | 所选模式被禁止时回退的模式，缺省为 `default` |
| `readOutsideProject` | 读取项目目录之外的文件：`allow` 或 `ask` |
| `pluginAllowlist` | 允许加载的插件名单 |
| `gateways` | 模型网关列表。对客户端只显示 id、名称、格式与地址，不显示密钥 |
| `disabledTools` | 禁用的工具名。运行时在调用时拦截，见「已知限制」 |
| `managedBy` | 记录由哪个系统管理该策略 |

策略文件可以通过环境变量 `PROMETHEUS_POLICY` 指定路径。未知键会被拒绝，格式错误时服务端拒绝启动。

策略的约束力取决于文件是否可写。`docker` 驱动以只读方式挂载策略目录，用户在容器内无法修改。`restricted` 与 `sandbox` 驱动下，策略文件位于租户目录内，租户进程理论上可以改写。这两种驱动的策略只能防止误操作，不能作为安全边界。

## 已知限制

- **PostgreSQL 路径**：通过 postgres.js 连接真实 PostgreSQL 的代码路径尚未对真实服务器做端到端验证。
- **Windows 沙箱**：Windows 沙箱运行时尚未在真实机器上端到端验证，目前只有命令构造的单元测试。
- **Docker 运行时**：尚未对真实 Docker 守护进程验证。
- **PI 运行时的工具禁用**：PI 运行时无法把被禁用的工具从模型的工具列表中隐藏，只能在调用时拦截。模型仍可能看到这些工具并尝试调用。
- **租户网关令牌**：租户访问模型网关的 JWT 有效期为 7 天。账号禁用或封禁后，Hub 会拒绝该账号的请求，但令牌本身不能单独吊销。
- **空闲检测**：空闲判断只看经代理的请求与 WebSocket 连接，不考虑正在运行的 Agent。Agent 在后台长时间运行时，租户仍可能被判定为闲置而停止。
- **管理界面**：租户实例与执行节点只有接口，没有管理后台页面。
